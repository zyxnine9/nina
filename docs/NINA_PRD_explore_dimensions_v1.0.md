# NINA 探索详情页 PRD

> 功能范围：思维方式、阅读人格、未读之境  
> 版本：v1.0  
> 日期：2026-10-11  
> 产品形态：微信小程序  
> 状态：需求与交互已确认，待视觉验收与实施

---

## 1. 背景

当前探索页仅展示「思维方式」「阅读人格」「未知领域」三张概览卡片。用户点击后只会看到“详情即将上线”的提示，无法理解结论依据，也无法继续探索。

本次需求为三个入口建立独立的全屏详情页。三页共享 NINA 的品牌语言，但分别回答不同问题：

| 入口 | 用户问题 | 产品角色 |
|---|---|---|
| 思维方式 | 我如何理解和回应书中的观点？ | 让用户看见自己反复出现的思维动作 |
| 阅读人格 | 我的阅读精神气质与行为节律是什么？ | 用人物原型建立认同，再用行为数据提供依据 |
| 未知领域 | 哪些尚未涉猎的方向可能适合我？ | 帮助用户跨出阅读舒适区，并提供低门槛起点 |

## 2. 产品目标

1. 让概览结论能够展开、解释并回溯到真实阅读证据。
2. 让三类分析具有不同的信息结构，避免复用同一个“AI 总结＋卡片列表”模板。
3. 在不替用户定义自己的前提下，提供具有情绪价值的自我理解。
4. 将「未知领域」从知识缺口改写为积极、个性化的探索邀请。
5. 为后续开发提供明确的数据契约、状态规则和可验收标准。

## 3. 非目标

- 不在详情页内切换另外两个探索维度。
- 不展示模型置信度、人格匹配百分比或领域推荐分数。
- 不使用雷达图、饼图、排行榜等测评化表达。
- 不根据单条阅读记录生成稳定结论。
- 不把未知领域描述成用户的缺陷或必须补齐的知识盲区。
- 不在本期加入即时重新生成、手动编辑分析或分享海报。

## 4. 全局体验规则

### 4.1 导航

- 用户点击探索页卡片后进入对应全屏二级页。
- 页面只呈现当前维度，不提供维度切换器。
- 系统返回键和顶部返回按钮均返回探索页，并恢复原滚动位置。
- 探索卡片右上角不展示含义不清的数字，改为方向箭头和具体预览文案。

### 4.2 可信度

- 每页必须说明分析依据，但不显示模型置信度。
- 原文、评论、书籍证据均可进入对应书籍或阅读瞬间。
- 返回详情页后，应恢复原展开项和滚动位置。
- 数据不足时展示“正在形成”，不得使用默认模板伪造结论。

### 4.3 稳定性

- 三类分析均使用稳定快照，不因重复进入页面而变化。
- 新阅读数据满足各维度更新条件后生成新快照，每天最多更新一次。
- 新版本只标记发生变化的部分。

### 4.4 加载与错误

- 点击入口后立即进入页面并显示局部骨架屏。
- 三个维度独立加载、独立失败、独立重试。
- 上游证据或推荐服务不可用时，保留已有内容并说明缺失，不阻塞整个页面。

## 5. 页面一：思维方式

### 5.1 页面目标

回答：**我如何理解、回应和处理阅读内容？**

思维方式不是智力评价，也不是理性／感性的二分测试。它描述用户在阅读时反复出现的动作，例如：

- 用具体例子检验抽象定义
- 对作者观点提出反例
- 将不同书籍连接起来
- 将观点转化为自己的判断

### 5.2 页面结构

1. 顶部导航标题「思维方式」
2. 分析依据，例如「基于 36 条评论与划线」
3. 一句统领全页的核心判断
4. 3–4 个最稳定的思维动作
5. 每个动作包含：
   - 书中的原文
   - 用户的划线或评论
   - AI 对思维动作的简短归纳
   - 「这种方式还出现于 X 条阅读记录」
   - 可原地展开的另外 2–3 组证据
6. 页面末尾文字入口「继续查看思维证据」

### 5.3 交互规则

- 不使用图表、百分比、雷达图或思维类型排名。
- 使用“原文—回应—归纳”的对话式证据卡。
- 多个思维动作可依次浏览；证据在当前页面原地展开。
- 点击原文或评论进入对应阅读瞬间。

### 5.4 数据不足

当缺少足够的主动评论或可锚定证据时：

- 显示「你的思维轨迹正在形成」。
- 说明仍需更多主动评论或划线反馈。
- 不根据纯阅读时长推断思维方式。

## 6. 页面二：阅读人格

### 6.1 页面目标

回答：**我的阅读精神气质与行为节律是什么？**

阅读人格同时包含：

- 精神气质与自我认同
- 阅读时间、持续性和沉浸方式

它不同于发现页的身份标签：发现页标签是一句可点击的自我描述；探索页阅读人格是一份由人物原型和行为节律共同构成的完整画像。

### 6.2 人物原型规则

人物来源优先级：

1. 用户读过的小说人物
2. 用户了解过的历史或文化人物
3. 数据不足时使用抽象原型，例如「夜航者」「漫游学者」

约束：

- 每个稳定快照只展示一个主代表人物。
- 不使用在世明星作为人格模板。
- 文案使用「你的阅读让人联想到……」，不得表达为「你就是……」。
- 必须标注人物来源作品。
- 不透露关键情节、关系转折或人物结局。
- 人物视觉采用原创气质插画，不复刻影视演员形象。

### 6.3 页面结构

1. 顶部导航标题「阅读人格」
2. 分析依据，例如「基于 275 个阅读日及读过的 42 本书」
3. 原创人物气质插画
4. 「你的阅读让人联想到……」及作品来源
5. 一句精神气质描述
6. 3–5 个「你与 TA 相似的地方」
7. 「你的阅读一天」行为节律：
   - 阅读高峰时段
   - 夜间阅读比例
   - 平均单次沉浸时长
   - 活跃阅读天数
   - 累计阅读时长
8. 将行为数据与人物特征一一关联的解释
9. 页面末尾「这像你吗？」：
   - 很像我
   - 一部分像
   - 不太像我

### 6.4 反馈规则

- 反馈进入下一次画像更新，不立即替换人物。
- 不提供候选人物切换，不把体验设计成“抽卡”。
- 当人物证据不足但行为数据足够时，展示抽象原型。

## 7. 页面三：未读之境

### 7.1 页面目标

回答：**哪些我尚未充分涉猎的领域，可能与已有兴趣发生连接？**

探索页卡片名称保持「未知领域」，详情页标题使用更具邀请感的「未读之境」，副标题为「三个你可能会喜欢的新方向」。

### 7.2 推荐规则

一个方向必须同时满足：

1. 用户没有涉猎或仅有极少记录。
2. 与用户已有兴趣、长期关注或思维方式存在可解释的连接。
3. 有可靠、低门槛的进入方式。

不显示推荐分数或匹配百分比，只使用「连接很强」「值得试试」「意外的可能」等定性语言，并解释依据。

### 7.3 页面结构

1. 顶部导航标题「未读之境」
2. 副标题「三个你可能会喜欢的新方向」
3. 三张纵向错落的“远方入口”卡片
4. 第一张默认展开；打开另一张时前一张自动收起
5. 每张卡片包含：
   - 领域名称
   - 领域的一句话介绍
   - 为什么可能适合用户
   - 与已有兴趣的连接依据
   - 一种主要进入方式
6. 进入方式可为：
   - 一本适合入门的书
   - 一组由浅入深的书单
   - 一个值得带着阅读的问题
   - 一条连接已有兴趣的阅读路径
7. 轻量反馈：
   - 想了解
   - 暂时没兴趣
   - 其实我读过
8. 主动作「从这里开始」

### 7.4 文案原则

- 不出现「你缺少」「知识缺陷」「必须补齐」等焦虑表达。
- 重点描述用户可能抵达哪里，而不是尚未掌握什么。
- 用户反馈后不立即移除卡片；下一版推荐再调整。

## 8. 视觉设计规范

### 8.1 设计目的

三个页面必须具有共同的 NINA 品牌感，但不能只是同一模板替换标题。视觉应服务于三个不同认知任务：对话、认同与探索。

### 8.2 美学方向

**编辑杂志感＋柔和自然意象。**

- 思维方式：左右错位的对话线，表现观点与回应。
- 阅读人格：人物肖像与行为数据层叠，表现精神气质。
- 未读之境：三扇错落的门或远方入口，表现开放与可能性。

### 8.3 色板

| Token | 色值 | 用途 |
|---|---|---|
| Deep Navy | `#123A6B` | 标题、关键文案 |
| Cloud White | `#F7FAFE` | 页面底色 |
| Mist Blue | `#CFE2F5` | 思维方式强调色 |
| Soft Mint | `#BFE4D7` | 未读之境强调色 |
| Dawn Gold | `#F1D49C` | 人格与探索的暖色点缀 |
| Lavender | `#D8D2F5` | 阅读人格的品牌浅紫 |

浅薰衣草属于现有 NINA 品牌色的窄范围延续；不得使用高饱和紫色或蓝紫霓虹渐变。

### 8.4 字体

- 标题：HarmonyOS Sans SC Bold
- 正文：HarmonyOS Sans SC Regular
- 阅读原文与人物引语：Source Han Serif SC

### 8.5 布局与组件

- 微信小程序纵向全屏二级页，无底部 TabBar。
- 左右安全边距 20px，间距使用 4px 倍数体系。
- 布局采用非居中的纵向编辑构图，允许错位、重叠和视觉连线。
- 卡片保持低阴影、浅描边和大圆角。
- 图标使用统一的细线专业图标，不使用 Emoji。
- 一屏只保留一个主行动点；其他动作使用文字链或轻量胶囊。

## 9. 数据与接口需求

### 9.1 思维方式

现有 `GET /explore/thinking` 需要从扁平 `items + evidence` 扩展为可直接渲染的证据组：

```json
{
  "summary": "你很少被动接受一个观点，更习惯用具体经验检验它。",
  "basis": { "commentCount": 36, "bookCount": 12 },
  "items": [
    {
      "id": "th_example",
      "name": "例证式思维",
      "description": "你常用具体经验检验抽象定义",
      "momentCount": 12,
      "evidenceGroups": [
        {
          "sourceMomentId": "...",
          "sourceText": "...",
          "userResponse": "...",
          "interpretation": "..."
        }
      ]
    }
  ]
}
```

### 9.2 阅读人格

现有 `GET /explore/persona` 只有时间统计，需要新增：

```json
{
  "summary": "你在安静时段进入深处，再用自己的经验完成判断。",
  "basis": { "readDays": 275, "bookCount": 42 },
  "archetype": {
    "kind": "fictional_character",
    "name": "悉达多",
    "sourceTitle": "悉达多",
    "portraitAsset": "...",
    "framing": "你的阅读让人联想到……",
    "traits": [
      {
        "name": "相信亲身经验",
        "description": "...",
        "behaviorEvidence": ["夜间阅读占 24%", "平均沉浸 40 分钟"]
      }
    ]
  },
  "rhythm": {
    "peakHour": 9,
    "nightRatio": 0.24,
    "avgSessionSeconds": 2400,
    "readDays": 275,
    "totalReadTime": 990000
  }
}
```

当 `archetype` 证据不足时，`kind` 使用 `abstract`，不得强行匹配人物。

### 9.3 未读之境

现有 `GET /explore/unknown` 的 `entryBooks` 需要泛化为多形态入口：

```json
{
  "summary": "三个你可能会喜欢的新方向",
  "items": [
    {
      "id": "u_phil",
      "name": "分析哲学",
      "affinityLabel": "连接很强",
      "reason": "...",
      "connections": [
        { "type": "topic", "name": "语言与真实", "evidenceMomentIds": ["..."] }
      ],
      "entry": {
        "type": "book | book_list | question | path",
        "title": "从语言如何塑造真实开始",
        "payload": {}
      }
    }
  ]
}
```

新增未知领域反馈写接口，记录：`interested | not_interested | already_read`。

## 10. 埋点与成功指标

### 10.1 核心事件

- `explore_dimension_open`
- `thinking_evidence_expand`
- `thinking_source_open`
- `persona_feedback_submit`
- `unknown_direction_expand`
- `unknown_feedback_submit`
- `unknown_entry_start`

### 10.2 首期观察指标

- 三类详情页打开率
- 证据展开率与原记录回看率
- 阅读人格反馈完成率
- 未读之境方向展开率
- 「从这里开始」转化率
- 详情页返回后的探索页继续浏览率

指标用于判断内容是否有理解价值，不以按钮点击最大化为唯一目标。

## 11. EARS 验收标准

### 11.1 导航与页面

1. 当用户点击「思维方式」「阅读人格」或「未知领域」卡片时，小程序应进入对应的全屏二级页。
2. 当用户从详情页返回时，小程序应恢复探索页原来的滚动位置。
3. 当某一详情页打开时，系统不应在页面内展示其他探索维度的切换入口。

### 11.2 思维方式

4. 当思维方式数据充足时，系统应展示一句核心判断和 3–4 个有证据支撑的思维动作。
5. 当用户展开一个思维动作时，系统应展示原文、用户回应、AI 归纳及更多证据。
6. 当用户点击一条阅读证据时，系统应打开并定位到对应阅读瞬间。
7. 当主动评论不足时，系统应展示“正在形成”状态，而不是生成无依据的思维类型。
8. 思维方式详情页不应展示图表、百分比或排名。

### 11.3 阅读人格

9. 当人物原型证据充分时，系统应展示一个代表人物、作品来源、相似特征和行为依据。
10. 当人物原型证据不足时，系统应展示抽象原型，而不是随机人物。
11. 人物描述不应包含作品关键情节或结局。
12. 当用户提交人格反馈时，系统应保存反馈，并在当前页面保持人物不变。

### 11.4 未读之境

13. 当未知领域数据充足时，系统应展示三个未充分涉猎且具有兴趣连接依据的新方向。
14. 当用户展开一个方向时，系统应收起前一个方向并展示推荐原因、连接依据和一种主要进入方式。
15. 系统不应显示匹配百分比、知识缺陷或必须补齐的表达。
16. 当用户选择「其实我读过」时，系统应保存反馈并用于下一次推荐更新。
17. 当用户点击「从这里开始」时，系统应按 `entry.type` 打开对应的书籍、书单、问题或阅读路径。

### 11.5 状态与可靠性

18. 当某一详情接口加载失败时，系统应只在当前页面展示重试状态，不影响探索页和其他维度。
19. 当证据或推荐书服务暂时不可用时，系统应保留可用分析并明确提示缺失部分。
20. 当分析数据没有发生实质变化时，系统不应在重复进入页面时生成不同结论。

## 13. 发布前检查

- 三页均为全屏二级页且不存在维度切换器。
- 所有结论均能说明依据或明确标注“正在形成”。
- 人物原型为单一对象、注明来源、无剧透、无演员肖像复刻。
- 思维方式无图表；未读之境无匹配分数。
- 所有证据链接、反馈按钮和返回状态恢复均可用。
- 色彩、字体、间距、图标符合第 8 节视觉规范。
